# Building Your Own Theme

Themes are built with the [Automatos Design Kit](https://github.com/AutomatosAI/automatos-design-kit), which is open source. Play and HUD are made in it too. The kit packs a theme into the one .autotheme file that Automatos installs, and its [guides](https://github.com/AutomatosAI/automatos-design-kit/tree/main/guides) cover what a designer works with: the package and its theme.json, the theme SDK (the one way a theme's code reaches Automatos), looks, and the phone block. With it, a theme can give the app its own frame, its own versions of some pages, pages of its own, its own colours, fonts and mascot, a set of looks with presets, and a phone skin.

## Before you start

- **Build on Studio.** This release of Automatos runs only themes built on Studio. A theme built on Classic installs, but you see Studio instead. See [Styles and themes](README.md#styles-and-themes).
- **Your looks.** To design a theme's settings and presets, see the kit's [looks guide](https://github.com/AutomatosAI/automatos-design-kit/blob/main/guides/looks.md).
- **Your phone skin.** To add a phone block, see the kit's [contract guide](https://github.com/AutomatosAI/automatos-design-kit/blob/main/guides/contract.md). What a phone gets from it is on [On Your Phone](on-your-phone.md).

## Trying and sharing a theme

| To do this | How |
| --- | --- |
| Try it in your own workspace | An owner or admin installs the file with **Install theme**. It installs as a private upload, and each member opts in before it runs for them. See [Install a theme from a file](installing-and-choosing.md#install-a-theme-from-a-file). |
| See what to fix | Read the [scan report](installing-and-choosing.md#the-scan-report) shown after the upload. A refused upload lists each problem: fix the theme and pack it again with the kit. |
| Offer it to every workspace | Submit it from **Marketplace → Themes** with **Publish theme**. Nothing is listed until a person at Automatos reviews and approves it. |
